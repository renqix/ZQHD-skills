# Seedance 2.0 视频 Skill

编写与接收生成提示词时，沿用 [提示词初稿与实际入口超限处理](../zqhd-video-ai/components/workflow/references/prompt-authoring-and-limits.md)：先按所选模型格式准确书写，结合参考图去掉无效重复；只有真实入口超限才返回二次语义检查。保留本技能的素材、模式和生成授权边界。

这是 Seedance 2.0 专用的导演与提示词 Skill。它输出可复制的正向/负向提示词、参考素材分工、镜头合同、平台待核对参数和验收清单；不把提示词写好等同于 API 已调用或成片已合格。

## 1. 适用边界

适用于：Seedance 2.0、用户明确指定的 2.0 Pro/2.0 Mini 变体、2.0 的文字生视频、图片生视频、参考生视频、首尾帧、视频编辑、延长、声音/对白、广告、汽车和连续分镜。

2026-10-30 核对的火山官方指南已列出 2.0 的参考、编辑、延长及组合任务，不再把编辑/延长视为 2.5 专属。功能与参数仍按当前 2.0 入口确认，不套用 2.5 的时长、素材容量、精确编辑或空间控制参数；普通三视图图片不等于白模空间控制。用户明确说 2.5 时使用独立 `seedance-25` Skill。

## 2. 2.0 事实与参数纪律

字节 Seed 官方资料确认 2.0 支持文字、图片、音频、视频四种输入，并强调多模态参考对表演、光影、运镜和音画联合生成的控制。官方 2.0 页面没有在本 Skill 中冻结跨平台统一的时长、分辨率、素材数量、价格或模型 ID。

- 当前平台的比例、时长、清晰度、音频开关、文件格式/数量和模型 ID，必须以当次官方界面或 API 文档为准。
- 只有当前官方页面或 schema 已核对的素材数量才列“官方/当前入口”；本轮官方 2.0 指南明确列出参考视频最多 3 段、合计不超过 15 秒，这一条不替代其它类型与混合总量核验。社区数量表不能自动成为跨平台硬限制。
- `2.0 Pro`、`2.0 Mini` 和平台显示名不自动等价；看到模型名后仍检查当前平台的实际能力。
- 不把 2.5 的 30 秒、最多 30 图/10 视频/10 音频、多轮延长和时间戳编辑写进 2.0 参数表。

写作先读 [references/prompt-writing.md](references/prompt-writing.md)，区分参考、编辑和延长触发语，按顺序镜头组织而不强制逐秒时间戳。查来源读 [references/sources.md](references/sources.md)；汽车读 [references/automotive.md](references/automotive.md)；复杂运镜、首尾帧或连续镜头读 [references/sequence.md](references/sequence.md)。

## 3. 默认工作流

### 第一步：锁定 brief

从用户已有信息提取：版本、任务类型、主体、场景、比例/时长/声音、参考素材、必须保留项、禁止项和交付方式。只询问会改变结果的缺口；没有参考图时不要声称“真实车型已锁定”。

### 第二步：建立参考素材合同

每个素材都写“负责什么”和“不负责什么”：

```text
@Image 1 只负责主车外观身份与车漆；不负责动作和内饰。
@Image 2 只负责内饰布局与材质；不负责整车外观。
@Video 1 只负责运镜、构图变化和动作节奏；不继承其中的车、品牌、人物和场景。
@Audio 1 只负责对白/音色/节奏；不自动复制原音乐。
```

若素材之间冲突，按用户明确优先级处理；没有优先级就减少素材或先问一个最小问题，不把“全部参考”理解成“全部照搬”。

### 第三步：先写镜头合同

每个镜头先写：

```text
镜头目的：观众必须看到什么
起始状态 → 触发动作 → 一个主要变化 → 摄像机如何覆盖 → 结束状态
主体运动：……
摄像机主运动：……
环境运动：……
声音/对白：……
```

一个短镜头默认只用一个主摄像机运动。不要把推、拉、环绕、俯冲、升降和穿越全部并列而不说明主次。

### 第四步：输出提示词包

按以下顺序交付：

1. `版本与任务`：明确是 Seedance 2.0 和 T2V/I2V/R2V/首尾帧/编辑/延长中的哪一种。
2. `参考素材分工`：逐项解释 `@Image`、`@Video`、`@Audio`。
3. `[Positive]`：自然语言、可直接复制，包含主体身份、动作顺序、镜头、光线、声音和结束状态。
4. `[Negative]`：写具体禁项，优先处理车型漂移、重复主体、错误品牌/车标、内饰错配、镜头跳变、自动字幕和水印。
5. `平台参数`：只列已核对值，其余写“当前平台待核对”。
6. `验收`：关键帧、声音、品牌、连续性和文字逐项检查。

`[Positive]` / `[Negative]` 是本地交付段名，不代表 API 存在独立正负字段；只有单个文本入口时，把必要约束合入实际正文。素材示例标签按真实界面/API 替换，不能把标签当作已经上传或绑定。

## 4. 2.0 汽车专项

汽车任务读取 [references/automotive.md](references/automotive.md)，至少建立车辆身份卡，锁定品牌/车型、车身比例、车漆、灯组、轮毂、车标位置、玻璃、门把手、外观套件和内饰可见布局。

- 外观多视图锁车型；内饰图单独锁座舱；运动视频只锁动作和运镜。
- 连续分镜固定车头朝向、行驶方向、车道位置、镜头侧别、光向、背景锚点和声音风格。
- 复杂换电、开合、装配动作拆为起始、接触、变化、对位、收束；不要只写“完成复杂机械动作”。
- 车标、车牌、仪表和中控文字默认不保证逐字正确；需要准确字形时规划后期叠加或局部处理，并逐帧验收。

## 5. 失败重写

先分类，再只改一个主变量：

- 车型漂移：提高主车画面占比，增加外观多视图，明确“唯一主车/不得改变车体结构”，减少背景车型。
- 内饰漂移：提高内饰图优先级，删去会引入错误座舱的参考，先做静态内饰镜头再接运动。
- 运动崩坏：拆成“起点→一个关键接触/变化→终点”，保留一个主运镜，降低背景复杂度。
- 首尾帧接不上：复述前镜尾帧的姿态、车位、朝向、光线和声音尾点，必要时增加桥接镜头。
- 对白错位：写明说话人、引号台词、先后、停顿和环境声；不要同时让模型生成未要求的旁白、字幕和音乐。
- 水印/字幕：写具体负面约束；若平台强制添加，说明本 Skill 无法承诺去除，改为核对导出权益。

同类问题连续两次失败后，提出更少参考、更短镜头、拆分镜头或后期处理，不无限堆形容词。保留失败版本和唯一改动记录。

## 6. 生成与验收门控

只写提示词时可以直接交付；实际生成时先展示 brief、参数和验收标准；用户已有明确生成授权且这些内容已确定时直接按范围提交，不重复确认。费用/模型/规格超出授权时再询问；LibTV 不因无法查询报价而阻塞已授权生成。用户要求“先看第一镜”时，执行单个提交—等待终态—导出—关键帧/声音检查—用户确认，未确认不生成后续镜头。

生成成功不等于内容合格。最终报告要区分：平台任务是否完成、文件是否导出、车型/品牌/动作/声音是否通过、哪些项目仍未验证。

调整方法只作为候选；改变模型、时长、镜头数量或再次付费生成须在本轮明确授权内，提交不明时先查原任务，不因重写提示词自动重投。
