# ZQHD Video AI（证据重建版）

编写与接收生成提示词时，沿用 [提示词初稿与实际入口超限处理](components/workflow/references/prompt-authoring-and-limits.md)：先按所选模型格式准确书写，结合参考图去掉无效重复；只有真实入口超限才按通道规则处理；官方 API 的两个模式不压缩，超限保留原稿并停止提交。保留本技能的素材、模式和生成授权边界。

2026-09-27 从 9 月 19 日三套合并前原件、《ZQHD-Video-ai-使用文档》及合并审查 HANDOFF 重建，不是丢失版本的逐字恢复。官方 H3 两份 txt 原样保留，组件参考保持来源结构。

返回交付统一读取[返回文件交付规则](components/workflow/references/return-delivery.md)。本技能负责模型格式和公共合同；原视频主体替换业务由`zqhd-car-modelvideo`负责，收到其固定素材映射时直接编译底层格式，不再次切回业务入口。

## 1. 按任务选择流程

- 完整视频/广告：读 [流程指南](components/workflow/guide.md)，按任务规模组织阶段。已有授权沿用，缺项集中提出，阶段产物写入现有项目目录。
- 单条提示词：直接进入对应模型指南，不展开整套生产流程。
- 单条素材生成：核对输入素材、提交设置与生成授权后，使用当前可用执行工具。
- LibTV 生成不查询扣点报价、单次费用，也不用额度接口推算费用——该 API 不返回这些信息。用户已授权生成时，按约定模型、规格与数量直接执行，不因缺少报价而暂停、重复询问或提醒。其他有报价能力的付费服务按其实际费用与授权执行；不自动充值或扩大生成范围。交付承诺锁定，把真实视频改成图片动画等交付形式变化需明确说明并取得对应授权。
- 分别记录提示词完成、供应商提交、文件取得和交付登记，不互相代替。

### 1.1 参考视频主体替换

指定原视频对象替换且尚未建立业务素材映射时，先由`zqhd-car-modelvideo`处理；已有映射时，只沿 [主体替换唯一合同](components/workflow/references/subject-replacement.md) → 已选模型的格式契约 → 实际入口参数。车辆附加规则仅在需要时读一次，不再加载完整广告流程。复用本轮来源、观察和固定快照；输入或问题未变，不反复看同一图、裁同一部位或重建身份档案。只做规则维护/问题诊断时不进入生成流程。

## 2. 模型与模式路由

### 2.1 H3

按 [H3 指南](components/h3/guide.md) 判断 T2VA、I2VA、FL2VA、L2VA、Ref2VA 五种模式。优云执行明确使用 H3 时，不得因共同关键词改走 Seedance。素材标签只能对应真实提供且已授权的文件。

官方 API 选择“超高细节 / 超高速”时，必读 [官方 API 通道](components/h3/references/official-api.md)，分别使用 `MiniMax-H3` / `MiniMax-H3-Highspeed`。完整中文提示词不压缩；7000 字符、素材角色与规格按该通道核验，不套 LibTV 的2000上限。

### 2.2 Seedance

先沿用用户指定的平台、版本与素材角色；版本未明确时先询问 2.0 或 2.5，不假定版本。模型本身未选定且会影响执行路径时先补齐选择。按 [Seedance 指南](components/seedance/guide.md) 选择版本，严格隔离两版参数。当前真实能力以平台/API 帮助为准，不把历史记录中的功能当作已验证能力。

### 2.3 Wan 3.0（万相）

读取 [Wan 3.0 写作规范](components/wan/guide.md)，区分文生、首尾帧、参考生成、源视频编辑和延长；素材用图片/视频/音频各自上传顺序编号。不能把 Wan 2.x 开源运行器参数、H3 字段或其它平台模型键套进 3.0。

### 2.4 Kling 4.0（可灵）

读取 [Kling 4.0 写作规范](components/kling/guide.md)，沿用用户选定的 4.0 / 4.0 Flash 与平台，区分全能参考、关键帧和编辑。截图或菜单显示名只确定候选模型；实际模型键、素材槽位和已开放功能由当前入口确认，不用旧版 3.0 或早期 Flash 教程代替。

## 3. H3 提示词层

先读 [H3 格式契约](components/h3/references/prompt-contract.md)，沿用已核验模式和本轮已读记录。首次使用某模式、格式有歧义或上游发生变化时，再读该模式的一份官方原文：[基础模式](references/h3/base-en.txt) 或 [Ref2VA](references/h3/ref-en.txt)；中文指南按需读，不同时加载所有版本。保留对应对齐指令、三核心字段或Ref2VA六段与标记。

H3 字段沿用官方格式，正文语言沿用共享契约中的用户中文偏好；台词、歌词与画面文字逐字保留用户原文。镜头需明确主体、动作、场景、相机、光影及声音，不用剧情概述代替镜头描述。Audio 标签与说话人编号需与真实素材及脚本对应。只有新广告策划才按需读 [模板](references/h3/product-ad-templates.md)；原片替换沿原镜头，不叠加广告六拍、卖点、字幕或额外运镜。删去未提供的 Video/Audio 引用。修改提示词时始终交付完整版本。

### 3.1 生成前素材要求

- H3 上传或生成前必读 [素材要求与失败恢复](references/h3/media-preflight-and-failures.md)：逐项核验图片、视频与音频，记录角色、顺序、数量、实际格式、尺寸、时长、大小及可读性；缺少必要检查或违反当前入口限制时先解决再提交。只写提示词则标注待检项，不上传。
- 录屏另查真实帧率与时间戳，720P 不代表固定 24fps。输入兼容性转码与最终输出规格分别记录；不得把固定 24 帧预处理、进入运行阶段或进度增长称为根因已证实或生成已成功。
- 平台限制按当次 schema 或官方说明核对，本机与优云按各自运行器合同，不把一处的限制写成全平台硬限制。

## 4. Seedance 提示词层

按所选版本读对应边界文件与 [汽车规则](references/seedance/automotive.md)。汽车任务另读 [车辆公共规则](references/vehicle-core.md)。输出八段：版本与工作流、路由理由与边界、车辆身份卡（非汽车任务省略）、参考素材合同、`[Positive]`、`[Negative]`、平台参数、交付状态与下一步。正负段名是本地交付格式；没有独立负面字段的入口，把必要约束并入正文，不虚构 API 参数。只把可见或用户确认的车型、车漆、灯组、轮毂、内饰写入身份卡；禁止重设计车辆或添加不存在的结构。白模/黏土等特定能力须核对当前版本是否支持。固定机位只限制相机，不代表主体必须静止。

写 Seedance 提示词前，按需在 Obsidian 内检索《📖Seedance 2.0 完整参考手册》与《🔧负面提示词_基准模板》，复用已有正负提示词资产。文件缺失则如实说明，不声称已加载。

## 5. Wan / Kling 提示词层

只加载已选模型的一份指南。正文默认中文，用户台词、画面文字、真实素材标签逐字保留；按该模型写素材指代、动作与镜头顺序、声音及必要约束，不套 H3 的三字段/六段。汽车任务读取[车辆公共规则](references/vehicle-core.md)；源视频替换继续沿用业务层已固定的素材映射和保留范围。每次修改交付完整正文，并把已确认平台参数、待核对项、提示词完成与实际生成状态分开。

## 6. 执行与交付

- LibTV 用已安装的 `libtv-cli`；H3 优云执行用 `minimax-mac-gpu`，并核验当前运行器与授权。
- 汽车及素材：身份卡、原文、无水印与交付承诺跨镜头保持。素材角色、顺序与文件路径明示；预演草图不自动替代原始参考。
- 所有返回文件沿[统一交付规则](components/workflow/references/return-delivery.md)登记；用户点名具体问题时独立诊断，不恢复默认返回检测。
- 原流程参考改编自 calesthio/OpenMontage（AGPL-3.0），保留来源说明。
- `scripts/check-upstream.sh` 只检查 MiniMax H3 官方 GitHub 原文，默认只读，明确更新请求才使用 `--apply`；它不检查 Wan、Kling 或 Seedance。其它模型沿各指南的来源和核对日期更新；访问受限写明未核对，不把社区教程升级成官方规范。技能维护不提交付费生成，也不代表实机验收。
