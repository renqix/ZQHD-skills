# 提示词初稿与实际入口超限处理

用于视频替换、封面、创意短片、首尾帧及其参考图制作。先按所选模型和实际模式写准确完整的初稿，再按当前入口的真实限制提交。本文统一语义与长度处理，不把 H3 的字段、声音段或字符上限套到图片模型、Seedance 或不同运行器。

## 中文正文与官方规范

按换老师 2026-10-26 的明确要求，新编写的所有项目提示词默认使用中文，包括替换视频、封面图、首尾帧、创意视频及配套参考图。专名、必须的模型字段、素材标签、对齐指令、时间格式和用户指定的台词/歌词/画面文字保持原文；已完成项目的历史原稿和固定技能快照不追溯改写。

- MiniMax [官网视频生成说明](https://platform.minimax.cn/docs/guides/video-generation)与[官网示例](https://platform.minimax.cn/docs/guides/video-prompt)直接提供中文提示词；明确写主体、场景、动作、镜头、光线、声音及每个参考的用途。
- MiniMax [官方 GitHub 改写技能](https://github.com/MiniMax-AI/MiniMax-H3/blob/main/skills/h3-prompt-writing/SKILL.md)仍要求结构化改写正文使用英文。这里采用中文是用户指定的本地创作策略；不能宣称官方已统一改成中文。保留该模式的结构和固定标记，官方原文文件不修改。
- 官方直连接口的 7000 字符说明不能覆盖第三方入口的实际限制。当前工作室 LibTV H3 以实取 schema 的 2000 UTF-16 单元为准；其他模型和通道分别核验，不将此数值写成全局规则。封面等图片提示词遵循实际图片模型，不添加 H3 的声音字段。
- 中文表达采用具体、可执行的自然句子；同一要求合并重复表达，保持实际动作、时序、替换范围与参考角色完整。格式中的英文值不翻译。

## 初稿：准确、具体，去掉无效重复

- 读取当前模式的官方规范；H3 使用官方基础三字段或 Ref2VA 六段，首尾帧保留对应对齐指令。描述可见动作、运镜和可听声音，不把剧情梗概、抽象赞美、处理器流程或审核口号填进生成正文。
- 先列本次必须保留的语义：主体身份与完整形体、部件关系、真实素材角色、动作及起止条件、时间顺序、场景和相机保留项、用户文字、声音方案及用户明确例外。未知项保留未知，不编造尺寸、切点或素材。
- 有完整图、多视图和细节图时，用准确标签说明每张图负责什么，把清楚可见且已由图承载的重复细节缩为必要身份锚点；仍要显式写出整体形体、局部与整体的关系及容易被原视频覆盖的关键差异。不能把“按参考图”当成完整车身描述，也不能仅留灯、轮圈、文字而丢掉车顶、座舱、尾部和整车体态。
- 同一约束通常只在最合适的段落写一次。字段间分别写身份、替换/保留范围与当前动作，不重复整套规则；易回退的切镜或重现处可简短重申同一完整主体，这是时间上的必要锚定，不是复制全部细节。首尾帧重点写起点到终点的连续路径，不反复逐项复述两张静态图。
- 关闭无条件自动压缩、截断、按句裁剪和“为凑固定字数而重写”。保存完整初稿、来源映射和必须保留项；不因为历史某个入口曾限 2000 字符，就预先把所有模型初稿压到 2000。

## 官方 API：完整正文，不压缩

MiniMax-H3 / MiniMax-H3-Highspeed 官方 API 按用户明确要求不执行下方二次优化：完整中文写词，最多7000字符；超限保留原稿、停止提交并明确反馈，不能自动删细节、截断、分拆text绕过上限或调用Context-IR改写。具体规格见 [官方 API 通道](../../h3/references/official-api.md)。LibTV MiniMax 按下方专门规则迭代；其它允许优化的入口继续使用原规则。

## LibTV MiniMax：2000字符，超限继续优化

换老师2026-10-26最新要求：连接LibTV的MiniMax视频模型设定2000个UTF-16字符上限，字段、标签、标点也计入。适用于替换视频、创意短片和MiniMax首尾帧。当前schema若更严格，按更小上限；即使schema暂未声明，也保留用户指定的2000上限。

完整读取并保存原稿；超限后使用中文合并重复、缩短句式、整理表达，逐轮保存候选和字符数。仍超限就继续优化，直到符合上限，取消此前仅一次优化的次数限制。最终稿必须保留全部实际制作语义、素材角色、时间、具体目标形体、完整替换范围、动作镜头、光影及声音要求，不能直接截断或删掉要求凑数。特别保留与旧对象不同的车顶、座舱和尾部等实际形体证据，不能用“按参考图”替代而只留下灯轮字标。首次超限适配由DeepSeek结合完整原稿、用户设置和定制要求、既有观察、实际参考图及原视频截帧理解内容主体、内容形式和表现方式，再判断必须保留与可合并表达；主动读图，不把纯文字压缩冒称画面理解。同一次编写留下简短取舍与画面依据，不另加独立审查。后续轮次复用同指纹画面观察，只为具体歧义补看，不重新识别全部素材。候选未变化、长度不再收敛或无法完整保留要求时停止空转，保留原稿和具体冲突。

此规则只授权同一提示词的文字优化，不重投生成、不重复冻结额度；已提交或结果未知的原任务先查回执。各项目暂停以其当前任务记录为准，不把特定历史项目名称写成所有任务的规则。官方API的两个模式仍不压缩；静态图片、Seedance和本机H3不继承这个2000上限或迭代规则。

## 其它入口：真实超限时二次检查

1. 从当次所选模型、模式与入口读取 schema 或明确的官方限制，按实际计数单位判断；未声明、未知或以 0 表示未设限时，不自行发明统一上限。保存模型键、上限来源、当前字数与原稿指纹。
2. 初稿能装下就原样提交。确实超限且尚未提交生成时，返回提示词编写阶段；工作室由 DeepSeek 做一次二次检查，可译成中文，合并重复或等价表达、移除无用套话，并结合已绑定参考图减少重复外观描述。不能删除必须保留的语义、改素材顺序、缩短动作或声音、改模型/模式/时长，也不能把整车形体退化成泛称。
保护的是全部实际语义，不把整段英文措辞、比例合同或声音描述逐字锁定。只对模型标记、用户原文及有实际意义的数值实行精确保护；长原稿分块完整读取，不修改原稿绕过读取限制。
3. 在本次文字适配中主动对照完整原稿、用户语境、真实参考图和原视频截帧，复用已有证据；记录必须保留、可合并表达、主体形体、内容/表现形式、动作时序、声音和标签。字数通过或关键词仍在不等于完整保留。只有用户明确要求独立审查或当前运行器契约确实需要时，才增加独立审查；不默认重跑媒体识别或逐字锁定自然语言。
4. 候选完整且满足当前入口上限，才沿原任务继续。仍超限、审查失败或关系无法核实则保留原稿并报告具体原因；不继续循环压缩，不静默删要求。已有供应商领取、提交或回执未知时，先查原任务，不以优化提示词为由新建生成。

正文修改必须沿原项目、原输入和已确认参数保存新版本；已有场景预演继续保留原来源及文件指纹，文字改写后记录新的提示词绑定；按当前用户要求不补做成品细节核对，也不能把未核对说成已通过。二次文字检查不扩大生成数量或付费授权，也不改写已完成任务的历史提示词。
