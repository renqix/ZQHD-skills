# Seedance 统一入口

编写与接收生成提示词时，沿用 [提示词初稿与实际入口超限处理](../workflow/references/prompt-authoring-and-limits.md)：先按所选模型格式准确书写，结合参考图去掉无效重复；只有真实入口超限才返回二次语义检查。保留本技能的素材、模式和生成授权边界。

本 Skill 只负责路由和提示词工作流，不把“写好提示词”当成已调用平台或已取得成片文件。先判断版本，再只使用对应版本的能力与参数。

## 1. 版本路由：先判断，后写参数

按以下优先级判断：

1. 用户明确写出 `Seedance 2.0`、`2.0 Pro`、`2.0 Mini` → 路由到 2.0。
2. 用户明确写出 `Seedance 2.5` → 路由到 2.5。
3. 未指定版本时，根据短镜头或延长/编辑等目标给出候选与理由，然后补齐 2.0 或 2.5 的选择；任务特征不能代替用户选定版本。
4. 线索冲突时说明能力差异并询问；已明确的版本直接沿用，不重复询问，也不静默切换。

路由完成后，输出开头必须写明：`版本：Seedance 2.0` 或 `版本：Seedance 2.5`，以及本次工作流类型。一个任务只能选一个版本；如确实要做两版，拆成两个独立提示词包和两个独立参数表。

## 2. 能力边界矩阵

| 能力 | Seedance 2.0 | Seedance 2.5 |
|---|---|---|
| 文字/图片/视频/音频参考 | 支持，按当前入口核对 | 支持，按当前入口核对 |
| 短镜头与普通连续分镜 | 主适用场景 | 可做，但不因此套用 2.0 规则 |
| 首尾帧 | 适用，写起始帧→中间变化→结束帧 | 适用，但按 2.5 工作流写 |
| 长叙事 | 不写成 2.5 的长叙事能力 | 主适用场景，单次最长 30 秒是官方发布层能力，入口仍需核对 |
| 视频延长 | 官方 2.0 指南已列出前后延长/轨道补全；按当前入口执行 | 支持延长，轮数与时长按当前入口，不无限外推 |
| 视频编辑 | 官方 2.0 指南已列出局部/全局编辑；不承诺精确秒点 | 官方强调时间戳级编辑；按当前入口限定区间与变更范围 |
| 绿幕 | 不写入 2.0 参数 | 适用，检查主体、阴影、反光和接触关系 |
| 摄像机视角编辑 | 不写入 2.0 参数 | 适用，按当前平台入口核对 |
| 白模/黏土空间参考 | 不默认承诺；只有当前 2.0 入口明确支持时才写 | 适用，用于空间、机位、阻挡、路径和节奏 |
| 动态参数 | 比例、时长、清晰度、素材数量、音频、模型 ID 均当次核对 | 同左；不得把官方发布层能力当成账号已开放 |

### 版本隔离硬规则

- 2.0 不继承 2.5 的时长、素材容量、编辑精度、空间控制参数或默认值；编辑/延长并非 2.5 独占，采用各自官方写法并核对当前入口。普通三视图图片不等于白模/黏土空间控制。
- 2.5 提示词包不得使用 2.0 的旧版素材数量、短镜头默认值、模型 ID 或平台限制。
- `2.0 Pro`、`2.0 Mini`、`star-video2-mini`、`star-video2.5` 等名称只有在当前平台实际核对后才能写入“平台已确认值”；它们不是跨平台通用 ID。
- 官方能力、当前平台已核对值、社区工作法和本地约定必须分栏书写，不能互相升级。

需要详细版本规则时：

- 2.0：读取 [references/seedance-20-boundary.md](references/seedance-20-boundary.md)。
- 2.5：读取 [references/seedance-25-boundary.md](references/seedance-25-boundary.md)。
- 汽车任务：必须读取 [references/automotive.md](references/automotive.md)。

2026-10-30 已刷新两版的官方写作指南与来源。2.0 默认按镜头顺序表达，避免强制精确秒点；2.5 按结构化事件、参考和任务触发词表达。各自的 `references/prompt-writing.md` 由独立版本技能维护，不在此复制。

## 3. 汽车公共规则与版本适配

汽车任务必读 [车辆公共规则](../../references/vehicle-core.md) 和 [Seedance 适配](references/automotive.md)。身份卡、素材分工、物理动作与制作约束由公共文件维护；版本参数只来自所选版本边界与当前入口，不在汽车层重新定义能力。原片替车还保留调用方的同时刻、构图和背景合同。

## 4. 统一输出格式

1. `版本与工作流`：明确 2.0/2.5、T2V/I2V/R2V、首尾帧、延长、编辑等。
2. `路由理由与边界`：说明为什么选该版本，并列出本次禁止使用的另一版本能力。
3. `车辆身份卡`：汽车任务必填。
4. `参考素材合同`：逐个写负责什么、不负责什么。
5. `[Positive]`：主体、动作顺序、主运镜、光线、声音、时间轴/起止状态。
6. `[Negative]`：本次必要的车型、镜头、编辑范围或声音/文字约束；没有独立负面字段时并入正文，不虚构 API 参数。
7. `平台参数`：分成“官方能力”“当前平台已确认”“社区/本地工作法”“待核对”，只填写所选版本。
8. `交付状态与下一步`：记录供应商完成、文件取得和交付位置；返回沿[统一交付规则](../workflow/references/return-delivery.md)。

实际生成沿用已有授权和已选路径。LibTV不查询或推算扣点报价；其它平台按实际费用与授权执行。用户只授权一镜或一段时，提交该范围并按统一规则交付，等待用户扩大范围后再继续。

## 5. 用户指定问题的改稿

用户明确提出问题后先分类，再按其要求改稿：车型漂移提高真实外观多视图优先级并减少竞争车型；内饰漂移提高座舱参考优先级并先做静态内饰镜头；运动崩坏拆成起点→一个关键变化→终点；连续性失败复述已选定尾帧；对白错位写明说话人、台词、时机和停顿。后续方案可建议更少参考、更短镜头/时间段、拆段、局部编辑或后期处理，不无限堆形容词。
