# MiniMax H3 视频提示词（通用 + 产品广告）

本 Skill 是原 `h3-prompt-writing`（通用官方规范）与 `h3-product-ad`（产品广告工作流）的合并版。官方格式基准始终是 MiniMax 官方仓库 [`MiniMax-AI/MiniMax-H3`](https://github.com/MiniMax-AI/MiniMax-H3) 的 `skills/h3-prompt-writing/`。

本组件负责 H3 模式与创作适配，字段、默认语言及长度规则只读[共享契约](references/prompt-contract.md)。沿用本轮已核验入口和素材；只写词不生成，实际提交前按[素材要求](references/media-preflight-and-failures.md)核对。原片主体替换使用[唯一替换合同](../workflow/references/subject-replacement.md)，直接进入对应格式，不叠加下方新广告流程。

官方 API H3 / Highspeed 必读 [官方 API 通道](references/official-api.md)，按对应模型完整写中文提示词。

## 第一步：判断模式

| 模式 | 输入 | 典型用法 |
|---|---|---|
| T2VA | 仅文字 | 纯文案片、概念片 |
| I2VA | 文字 + 1 张首帧图 | 用主视觉开头，往后展开动态 |
| FL2VA | 文字 + 首尾 2 张图 | 从起始状态过渡到结束状态 |
| L2VA | 文字 + 1 张尾帧图 | 结尾定格，前面倒推过程 |
| Ref2VA | 文字 + 任意参考图/视频/音频 | 全参考：人物、主体、场景、动作、风格一致性 |

判断依据只有两条：用户给了什么素材，以及素材要求"必须是首/尾帧"还是"只提供一致性参考"。关键帧模式与全参考模式不能混用。

## 第二步：读取对应规范

- T2VA / I2VA / FL2VA / L2VA：按[共享契约](references/prompt-contract.md)使用对应三字段和对齐指令；首次/有歧义时核对 [base-en.txt](references/base-en.txt)，中文蒸馏按需读。
- Ref2VA：按共享契约保留六段和实际参考关系；首次/有歧义时核对 [ref-en.txt](references/ref-en.txt)，中文蒸馏按需读。
- 用户要求从零策划产品/汽车广告时，才叠加第四步及[广告模板](references/product-ad-templates.md)。仅替换原视频对象时保留原镜头，不因出现汽车而改成新广告。

## 第三步：读取共享格式契约

字段顺序、关键帧对齐指令、参考标签、时间写法和默认语言统一遵循 [H3 提示词格式与语言契约](references/prompt-contract.md)。本指南只叠加创意和产品工作法；最终正文仍按当前模式的一份官方原文核对。

## 第四步：产品广告工作流（叠加在第三步之上）

仅适用于本次明确要求新广告策划；用户已有原片、分镜或替换范围时沿原方案，不自动加六拍、卖点或品牌露出。

### 4.1 先收集产品五要素

1. 品牌与型号的唯一称谓；
2. 外观锚点：颜色、材质、比例、线条、Logo 位置；
3. 核心卖点，按重要性排序并转成可见动作；
4. 台词、Logo、车名、口号、屏幕文字原文；
5. 时长、画幅与发布平台（横屏 16:9 / 竖屏 9:16）。

已有信息足够时直接开工，不重复询问；只有真正影响模式、产品身份或最终画面的缺失项才问。

### 4.2 广告六拍结构（按 4–15 秒压缩）

开场钩子 → 产品亮相 → 卖点展示 → 场景体验 → 情感收尾 → 品牌露出。

- 4–8 秒：保留钩子、亮相、一个核心卖点、品牌露出；
- 9–12 秒：可加第二卖点或一段简短使用场景；
- 13–15 秒：完整六拍，但每个镜头仍只承担一个主要信息。

不要为了凑齐六拍牺牲动作连贯性。首尾帧任务通常优先单镜头连续过渡；产品参考图任务把外观一致性放在镜头数量之前。

### 4.3 产品与汽车红线

真实车辆任务先读 [车辆公共规则](../../references/vehicle-core.md)，沿用其身份卡、参考分工、物理动作和制作约束；以下只补充产品广告表现。

- 主体的颜色、材质、比例、Logo、关键线条和屏幕界面不得漂移。
- 从零策划新能源广告时，充电、换电或能量变化优先用光影、机械动作和提示音；原片替换不凭该默认删除用户要保留的已有烟雾或其它效果。
- 真实参考车辆不自行重新设计，不新增不存在的灯组、格栅、轮毂、车标或车身结构。
- 一个卖点对应一个清晰可见的动作或特写，不用抽象形容词代替证据。
- Logo、口号、车名、界面文字用双引号逐字保留。
- 新广告未要求叠字时不新增字幕或额外标志；原片已有文字和目标本身车标按用户要求保留，不以“无标志”删掉目标身份。平台水印能力以实际入口为准，不靠一句提示词承诺移除。

## 第五步：提示词生成重点

### 5.1 主体身份与视觉锚点

- 先锁定主体是谁、外观是什么、位于哪里，以及哪些特征必须全程保持。
- 人物写清年龄段、发型、服装、体态和可识别特征；产品或汽车写清品牌、型号、颜色、材质、比例、关键线条、Logo 位置和界面特征。
- 参考素材只写实际希望保留的特征，不凭空增加参考图中不存在的结构、配件、文字或人物关系。

### 5.2 一个动作与一条镜头路径

- 每个镜头优先安排一个主要动作，并写清动作的起点、过程、结果和连续性。
- 每个镜头只设置一条主要运镜路径：景别、主体位置、运镜类型、方向、幅度和速度；微小视角变化优先写成连续运镜，不堆叠互相冲突的镜头指令。
- 用可以被看见的动作表达卖点和情绪，不用“高级、震撼、电影感、极致”等抽象词代替画面证据。

### 5.3 声音、对白与画面文字

- `overall_soundscape` 写环境声、物理动作声和非语言人声；`non_diegetic_music` 只写观众听到的配乐、乐器、速度、节奏和动态。
- 发声者按首次发声顺序稳定编号 `(S1)`、`(S2)`；对白和歌词逐字放入 `<d>[语言] 原文</d>`，不擅自翻译或改写。
- 旁白写明 `says in an off-screen voiceover`，并说明画面人物嘴唇闭合；画面内文字使用双引号保留原文和标点。
- 声音、对白和文字必须能在对应时间线内完成，不能只写抽象的“有感染力的声音”或“震撼配乐”。

### 5.4 单变量修改与完整重写

- 用户修改时覆盖本次明确要求的主体、动作、镜头、光线、声音、对白、文字或负面约束；保留其它已确认内容。诊断失败时可只改一个主变量，不把它当成拒绝用户同时修改多项的限制。
- 每次输出都重新检查模式、素材标签、时间戳、发声者编号和字段顺序；不要只返回局部替换片段。
- 首次输出直接给完整提示词；用户集中修改后，再给完整的第二版提示词。

## 第六步：输出提示词

1. 一句中文说明模式判断与理由；
2. 完整 H3 提示词（代码块，字段名用官方英文原文）；
3. 素材角色与素材顺序清单（`<Picture N>` / `<Subject N>` / 首帧 / 尾帧 / 参考图）；
4. 提示词所依据的素材角色、画幅、时长和声音方案；
5. 仍无法核实且会影响结果的关键缺口；已有确认直接沿用。

语言与字段沿用 [共享提示词契约](references/prompt-contract.md)，不在入口另设默认值。

首次输出必须是完整的 MiniMax H3 格式，不能只给提纲或简化版；已有直接生成授权时不强制等待一次修改回合，修改后重新输出完整版本，而不是只给局部替换片段。

## 常见坑与官方 Tips

- 时间线总长必须与实际入口支持且已选定的请求时长一致，不能在结束时间之后继续写动作或台词。
- 参考标签必须在所有段落中保持一致，不要定义没有实际对应素材的标签。
- 避免剧情总结式写作：不复述故事梗概或抽象情绪，一切描述都落在可见画面、可听声音和参考内容出现的精确时间点上。
- 关键帧模式必须写清首帧/尾帧如何接入时间线。
- 用具体视觉与声音细节代替抽象形容词。
- 模式判断必须和素材用途一致；关键帧模式与全参考模式不能混用。
- 提示词正文只写画面、声音、对白、文字和必要的红线。
- 参考音频只在确有对应素材和明确用途时定义，不要凭空增加 `<Audio N>`。

## 与官方同步

- 官方格式基准：MiniMax 官方仓库 [`MiniMax-AI/MiniMax-H3`](https://github.com/MiniMax-AI/MiniMax-H3) 的 `skills/h3-prompt-writing/`。
- `references/base-en.txt`、`references/ref-en.txt` 是官方原文，保持与官方 `main` 一致；`agents/openai.yaml` 与各中文 guide 为本机自有，不随官方覆盖。
- 检查更新：运行 `scripts/check-upstream.sh`（只读检查，不改动文件）；需要同步官方原文时运行 `scripts/check-upstream.sh --apply`。
- 官方 `SKILL.md` 的规则变化不自动覆盖本文件（本文件是中文增强合并版），脚本会报告官方变化；人工合并后运行 `scripts/check-upstream.sh --ack` 清除提醒。
