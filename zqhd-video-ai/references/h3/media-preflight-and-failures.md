# MiniMax H3 素材要求、预检与失败恢复

所有 H3 生成入口在上传或提交前使用本文件；仅写提示词时建立素材表、标明未核验项即可，不上传、不生成。规则针对 H3 视频，不能套到 MiniMax image-01、语音或音乐模型。本文件不授予付费、重试、换模型或降低交付规格的权限。

## 1. 先确定入口与素材角色

先记录模型、版本、平台/运行器和模式。LibTV、MiniMax 官方 API/MMX、优云自部署 Runtime、本机 ComfyUI 分别核对当前 schema、帮助或 `prepare` 计划；不能把 API 参数套给本机或把本机能力当作云平台能力。

为每份实际输入登记：路径/上传标识、文件大小与 SHA256、类型、顺序、用途、必须保留项、允许变化项、检查结果。引用编号必须与最终上传顺序相同。对同一内容与同一入口可复用检查；文件、顺序或规则改变时重查受影响项。

- **图片**：必须可打开并实际查看。确认主体身份、左右、比例、细节和可读文字；分清首帧、尾帧与身份/风格/分镜参考。两张图不自动等于首尾帧。多视图板用于锁定同一物体，不自动拆成多个镜头；编号和说明文字不得生成到主体上。
- **视频**：必须可完整解码；查看首中尾、切点和关键动作，记录尺寸、显示比例、编码、时长、真实帧率/时间戳和音轨。说明借用身份、动作、构图、运镜还是环境。原片替换任务用原片或核验过的兼容副本，保留原片作为时间轴与制作依据。
- **音频**：必须可解码；需要判断语音、音乐、节奏或同步时实际试听并登记用途、起止点、编码、采样率、声道和时长。视频内有音轨不代表已接入独立音频参考；“参考音色”不代表逐样本保留原音。
- 缺文件、不能解码、引用不匹配、超出当前入口限制时先解决再提交。无法查看/试听的内容标为未核验，不编造素材描述。声音只是可选项时不为凑格式添加音频。

## 2. 托管 H3 的技术基线

以下来自 2026-10-15 查验的 [MiniMax 官方 H3 媒体预检](https://github.com/MiniMax-AI/cli/blob/main/skill/h3-video/references/h3-video.md)。平台包装层可更严格；实际提交须同时满足适用的官方约束与当前入口约束。出现冲突先确认入口，不选更宽松的旧值。自部署不直接使用本表作硬限制。

| 素材 | 官方 H3 基线 | MMX 本地文件入口的额外限制 |
| --- | --- | --- |
| 首帧/尾帧 | 每种最多 1 张；不能与全参考模式混用 | 每张最多 30 MB |
| 参考图片 | 最多 9 张；JPEG/JPG/PNG/WebP；每边 256–5760 px；宽高比 0.4–2.5 | 每张最多 30 MB；CLI 还识别 HEIC/HEIF，但不据此推断其它入口支持 |
| 参考视频 | 最多 3 段；MP4/MOV；H.264/H.265；23.976–60 FPS；每段 2–15 秒，合计不超过 15 秒 | 本地入口只收 MP4、每段最多 50 MB；其它受支持输入按官方 URL/文件 ID 方式 |
| 参考音频 | 最多 3 段；MP3/WAV；每段 2–15 秒，合计不超过 15 秒 | 每段最多 15 MB |

混合参考总数最多 12；参考音频至少同时配一张参考图或一段参考视频。MMX 完整请求体上限 64 MB，Base64 会增加体积，单文件都合规不代表总请求合规。较大素材使用入口支持的文件上传/文件 ID 或已授权的可访问 URL，不为通过限制自动公开私人素材。

LibTV 的实际输入、提示词上限、输出清晰度和时长枚举由 `libtv model` 当前 schema 核对。输入 720P 与输出 768P 是独立设置；不得将某次 768P、10 秒或某个画幅固化成通用默认。优云检查实际 Runtime 支持的素材类型、数量、MP 和时长；本机检查 Director 的槽位、画布、采样和 `prepare` 计划。缺少某类支持时先说明，不假装已接线。

## 3. 录屏必须同时检查尺寸、帧率与时间戳

用 `ffprobe` 记录视频/音频编码、像素尺寸、显示比例、时长、文件大小、`r_frame_rate`、`avg_frame_rate`、`time_base` 与实际解码帧数。容器 `nb_frames` 可能不准确；需要时用 `-count_frames`。以下为只读检查示例：

```bash
ffprobe -v error -show_streams -show_format -of json INPUT.mp4
ffmpeg -v error -i INPUT.mp4 -f null -
# 录屏、两种帧率不一致或兼容性异常时，再查实际帧时间戳。
ffprobe -v error -select_streams v:0 -show_frames \
  -show_entries frame=best_effort_timestamp_time,pkt_duration_time -of json INPUT.mp4
```

平均 FPS 小于 60、扩展名为 MP4、文件缩到 720P，都不能单独证明兼容。对 VFR/高帧率录屏检查相邻帧时间间隔和异常跳变；两项 FPS 都是 24 也不代替时间戳核验。

## 4. 只在需要时制作兼容副本

保留原片。超出当前规格、确认存在高帧率/VFR兼容风险，或用户明确要求时，制作固定 24fps 的 H.264 副本。缩到 720P 只在用户指定或当前限制需要时进行，不默认降低所有素材清晰度。保持显示比例和完整构图；处理旋转、非方形像素时核对显示效果。音轨兼容则流复制，不兼容时记录重编码及影响。

下例适用于已确定高度 720、方形像素的横向素材；竖片或平台要求长边上限时按实际规格调整缩放规则，不拉伸、不擅自裁切。目标文件必须是新文件，`-n` 防止覆盖：

```bash
ffmpeg -n -v error -i SOURCE.mov -map 0:v:0 -map '0:a:0?' \
  -vf 'scale=-2:720,fps=24' -c:v libx264 -preset medium -crf 18 \
  -pix_fmt yuv420p -fps_mode cfr -c:a copy -movflags +faststart REFERENCE-720P-24fps.mp4
```

转码后核对两项 FPS 为 `24/1`、帧间隔均匀、尺寸/显示比例、时长/起点、音轨和完整解码，并与源片同时间点对照首中尾/切点。固定 FPS 是按原时间轴重采样，不用全段变速、补静帧或循环掩盖时序错误；记录丢/补采样及帧边界毫秒级差异，不承诺逐帧保留。

## 5. 提交前与失败恢复

预检记录至少包括：`入口/模型/模式`、`有序素材及角色`、`原件→副本映射`、`技术检查`、`视觉/声音检查`、`输出参数`、`未解决项`。必要检查通过后才回读最终节点与参数，并按已有明确授权单次提交；上传/替换素材不等于授权再次生成。

保存任务 ID、提交参数快照、素材标识/顺序、终态和原始错误。只有已回读并按当前平台状态定义确认失败终态，才报告失败；空 URL、超时、无任务号或 history 缺失单独不证明失败。已失败任务中的 `failedCategory=UNKNOWN` 仅表示原因未细分，不据此认定审核、水印、提示词长度或分辨率是根因。能查询原始响应时保留错误类别和 trace_id，不保存凭据；返还提示不证明到账。

画布当前设置可能被其它会话改动，不能替代历史收据。原节点有其它任务或模型配置时保留它，获准重试后新建独立节点并复用已核验素材。提交不明、超时、无任务号或 history 缺失时先查收据/队列/历史，保持 `uncertain`，不重复 POST。运行器自带等待时等待同一进程；失败后只修已查明项，重试须在本轮授权范围内，下载失败只恢复同一结果。

## 6. 已验证案例与证据边界

2026-10-15 的录屏仅缩到 720P 后仍保留 120fps 特征并再次失败；两次上游错误类别均为 UNKNOWN。改为固定 24fps、720P、H.264 后，以 H3/768P 按授权重试一次成功，实际输出 1344×768、24fps、10.125 秒，整段解码通过。

这是本例可用的兼容性恢复方案，不能证明帧率是此前失败的唯一根因，也不排除服务状态变化。它不意味着所有 H3 素材必须 720P/24fps。这是输入兼容性历史证据，不建立返回验收；返回沿[统一交付规则](../../components/workflow/references/return-delivery.md)记录原任务和原文件。运行进度增长不等于供应商完成，不把未取得文件写成已交付。
