# zqhd-car-modelvideo · 汽车看板与原视频车辆替换

中文交流，称呼用户为“换老师”。支持只制作车辆参考图，以及确认参考图后替换原视频车辆两个分支。“翻拍”以原视频为时间与镜头基准，不自动重写背景或加入新镜头。仅创建/修改本技能时不生成看板或视频。

## 1. 接收实车照片，建立身份档案

- 查看同一台目标车的多角度照片，保留原文件和来源顺序；混入其它车辆或改装版本时先分组。
- 读取本技能内置的 [车辆看板制作](references/vehicle-boards.md)，按实拍证据、物理左右、细节档案、图片生成与人工核验流程工作，无需另装旧车辆看板技能。
- 门把手、车窗、车灯状态或左右图案不确定时集中询问；已有明确答案沿用，照片未显示的细节保留未知。图片生成遵循当前环境的 `imagegen` 技能和工具。
- 此阶段先制作看板，不默认索取或上传视频。交付范围按第 3 节选择。

## 2. 制作两张看板，等待用户确认

按 [车辆看板制作](references/vehicle-boards.md) 实际生成、核验并交付：

1. **01-汽车八视图.png**：两行四列，正前、正后、左侧、右侧及四个45°角度。
2. **02-细节约束看板.png**：同一张图锁定左右贴纸/拉花、文字、车标、牌照、轮毂/卡钳、灯组、门把手、玻璃、车顶附件等有证据的细节。

看板本身按内置车辆看板流程制作；过程资料内部保存，正常只展示这两张图。分别说明重建角度、不可读文字和未解决项。左右是**车内面向车头的物理左右**，不能仅凭车头朝屏幕哪边推断。

**必须展示实际两张图并请用户确认车型外观、颜色、左右细节和状态。确认前不得提交视频生成。** 此步骤来自用户要求的工作流程，不是额外的付款审批。没有答复不算确认；用户提出修正时，修正受影响看板、重新检查并再次展示。不能把文件存在、模型自述或过去另一辆车的确认当成本次确认。

用户已明确确认同一套看板、目标车未改变时，复用确认记录，不重复制作。只上传过看板而没有确认记录时，先展示并确认。用户后来明确改变该确认流程时遵循最新指令。

## 3. 选择交付范围，再索取原视频

展示两张看板后，在索取或上传替换视频之前询问：“换老师，这次是只保留车辆多视图和细节图，还是继续用它们替换原视频里的车辆？”可提供“只保留两张图”和“继续视频内容替换”两个选项。

- 用户本轮已明确选择其中一种时沿用，不重复询问；只上传照片或直接调用技能不代表选择视频替换。
- **只保留两张图**：完成看板核验、按用户反馈修正并交付两张 PNG，任务结束。不索取视频、不上传到视频平台、不创建视频任务。
- **继续视频内容替换**：先确认看板，再请用户上传要翻拍的原始视频文件。上传请求用正常对话，不放入仅接受文本的问答工具。原视频已经上传且可读时直接复用，不要求重传，但仍须确认本轮替换意图。
- 未选择时可以继续不依赖视频的看板工作，不默认进入视频分支；没有答复不算选择或确认。
- 已选替换但视频未到时等待素材，不使用旧生成片代替。原片中多车或遮挡导致替换对象不明确时，展示实际帧并询问目标。

## 4. 核对原视频，建立保留合同

用 `ffprobe` 记录视频/音频流、实际像素尺寸、显示比例、帧率、帧数、时长与时间基准；查看首中尾及所有转场/遮挡/状态变化，必要时高密度抽帧。声音要保留时核对源音轨。记录以下默认保留项，并只列出用户指定的例外：

| 项目 | 默认规则 |
| --- | --- |
| 时间 | 整段原片，不截选、不延长、不压缩时长；事件发生时间、节奏、切点不变 |
| 背景 | 原有场景、窗框/前景、隧道、经过的车辆/车厢、地平线、光照变化及出现顺序不变 |
| 相机 | 原构图、源相机投影、机位高度、视角、运动轨迹和速度变化不变；不加低角度、环绕或切镜 |
| 目标车 | 只将指定车辆的身份与外观换成已确认目标车；位置、朝向、尺度变化、速度、轮胎接触和遮挡继承原片 |
| 灯与轮 | 沿用原片或用户指定的状态及切换时刻；静止轮辐保持角度、转动轮胎符合运动；不能提前亮灯或自行开始路跑 |
| 其它内容 | 人物、其它车辆、反射、道具保持；目标车的投影、反射和接触影与新外观合理对应 |
| 声音 | 默认复用原音轨，不重新生成对白或配乐；无音轨保持无音轨 |

原片中的模型车/窗台小车与真实道路车辆必须作为不同阶段描述，背景移动不代表窗台车轮转动。用户指定某个视角时按物理侧别核验；不能用镜像满足侧面要求。

将用户指定例外独立写明，如“道路段改雨夜”或“接触道路后亮灯”。这是对保留合同的局部覆盖，不允许连带重写其它背景、时长或相机。不要把以往ET5T、某车牌、10秒、2K、雨夜或特定运镜写成所有任务的默认。

## 5. 确认后执行车辆替换

- 两张看板已确认、原视频可读、目标车明确且关键未知项已解决后，按用户已授权的翻拍请求直接执行一次，不再额外要求批准提示词。
- 复用本轮已选平台、模型和质量参数；仅写提示词/暂不生成时不提交。没有平台上下文时，沿用本技能的 LibTV MiniMax H3 全能参考路径，提交前说明选择；用户指定本机则走本机，不自行转云端。分辨率优先保留原视频等级或用户指定等级，不暗中降低。
- LibTV：读 当前环境已安装的 `libtv-cli` 技能及 `zqhd-video-ai` 的当前 H3 指南。通过 `libtv model` 和子命令帮助核验实际 schema。素材数量、时长或模式不支持时，先说明保留合同受限；不能静默截短素材、降级或换模型。源时长超过单次上限时，先提出保持完整时长的分段/其它模型方案，确认后执行，不能自动扩大生成数量。
- 本机：读 当前环境已安装的 `minimaxh3-m1max-video` 技能，沿用健康核验、独立工作流、预检、单次提交收据和恢复规则，不覆盖模板、不重复提交或重启在跑服务。
- 独立保存本次项目、完整提示词、平台参数、素材顺序和唯一任务收据。参考视频用**上传的原始文件**；八视图和细节板分别锁定整车与局部。不用旧生成片反复翻拍，以免继承它的背景或灯轮错误。
- 用平台实际素材编号编写完整提示词；H3 使用六段格式和 retention_analysis。编译时读 [提示词与验收要点](references/prompt-and-qa.md)。不把看板标签、箭头和解释画到车上。
- 回读并核对模型、实际时长设置、分辨率、比例、数量、素材顺序及提示词长度，然后提交一次。平台时长按整数或内部帧数对齐时，先检查能否覆盖源片完整时间轴并精确交付；不能把整数设置误称为原片时长。

## 6. 原时长交付与验收

生成成功后保留平台原输出，检查实际规格并整段解码。与**原始视频同一时间点**并排核对：背景与切点、相机、目标车位置/比例/朝向、遮挡、车漆、左右细节、轮辐及灯状态。高风险文字、车标、轮毂和附件按看板逐项记录“通过/未通过/不可核验”。小字无法读清时不能宣称完全一致。

- 平台多出对齐帧时，只在确认源片完整内容和事件时间保留后，裁去源结束点之后的多余部分；不能用全段加速/减速把错误节奏压回原片时长。生成过短或事件错位时视为未达标，不用补静帧/循环冒充完整原片。
- 尽量沿用源帧率、时间戳和显示比例；遇可变帧率或模型输出帧率不同时，如实记录重新采样范围与容器时间基准，不能声称逐帧或逐像素保留。
- 默认将原音轨按源时间轴合成到独立最终文件，优先流复制，检查音视频起点、末尾和同步；生成音频不能冒充原声。未试听项标为未验收。
- 文件可读、整段解码、画面通过、原音保留、iCloud写入和手机收到分别报告。生成模型不保证像素级不变；背景明显重绘、缺失、提前路跑、新增运镜、灯轮状态错位均不得标为合格。
- 失败或不合格保存具体问题和收据，不自动增加付费重试/种子批次。用户要求再来一版时，只修正当前已指出问题并保留其它合同；仅改提示词时不生成。

用户已要求有产出就发时，可将可播放的未达标结果明确标为“预览”交付，并列出缺陷；否则未达标文件保留为待验收，先报告。沿用用户指定接收位置；本机技能或本轮明确要求手机交付时使用用户已配置的手机接收目录（macOS 可为 iCloud Drive 下的 `视频生成-手机接收`），核对源目标大小、SHA256及目标可读。没有手机端证据不能称收到。最终给视频链接、实际尺寸/时长、完整提示词位置、任务ID、通过范围和不足。
