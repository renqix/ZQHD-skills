# 标准视图提示词与验收

实际开始生成或修正时读取本文件。所有占位内容用本次 manifest 的事实替换；未知项先走 SKILL.md 的询问步骤。原图与生成图的作用要分开写。

以下单视图与局部素材用于内部生成、核验和排版。最终交付固定为一张八视图 PNG 与一张细节约束 PNG，不逐张展示中间图、不交付独立角度/局部、不分页。

## 车辆坐标与八视图

左右基于坐在车内面向车头，不基于观看者。角度是相机观察方向，转动的是观察位置，车辆身份/图案不改变。

| ID | 输出 | 可见车面与图案来源 |
|---|---|---|
| F | 正前 | 前保险杠、前灯、前标、前牌照；不强行露出两侧门贴 |
| B | 正后 | 尾门、尾灯、后标、型号字、后牌照；两侧外观不移到尾门 |
| L | 完整左侧 | 左侧门、左侧玻璃、左侧拉花与两只左轮 |
| R | 完整右侧 | 右侧门、右侧玻璃、右侧拉花与两只右轮 |
| FL45 | 左前45° | 正前+车辆左侧，引用左侧细节 |
| FR45 | 右前45° | 正前+车辆右侧，引用右侧细节 |
| RL45 | 左后45° | 正后+车辆左侧，引用左侧细节 |
| RR45 | 右后45° | 正后+车辆右侧，引用右侧细节 |

八格顺序为 `F B L R / FL45 FR45 RL45 RR45`。左右不对称时，至少将两侧贴纸和相应斜视分别比对，不能只抽查一个侧面。结构自然对称也不证明饰件对称。

## 每张生成前的引用准备

建立本次引用清单，例如 `输入1=S03 右前实拍，整体几何；输入2=S08 右侧实拍，D03右后窗贴纸；输入3=S05 实拍，车尾；输入4=已验收锚点，仅辅助车漆与整体体态`。写清可见/不可见面。不要把某图里的右侧贴纸用作左侧细节。

完整单车照片优先锁整体；小图案用原图局部 viewport 参考补强。按工具实际接受的图像机制上传，不把文字中提到的 `Dxx` 当作已传入图像。路径参考需真实存在且已查看；无路径的会话图片按工具文档选择最小最近图范围。

## 单视图生成模板

```text
用途：汽车视频生成的标准身份参考。输出一张完整单车照片，不画看板、不加文字标签。
输入角色：{按实际输入顺序列出S编号、物理侧别、整体/细节用途；生成锚点注明辅助身份}
主体：参考中同一台实际车辆，{车体类型、视觉漆色、材质、黑银装饰、玻璃窗框}。
本次观察角度：{F/B/L/R/FL45/FR45/RL45/RR45的中文定义}。车辆左/右按车内面向车头定义。
相机：{该角度的方位}，中性产品摄影、长焦感的低畸变透视、车身中部附近高度，完整车体、四周留边。
环境：干净浅灰棚景、柔和中性光、真实轻柔接地阴影，背景不继承原旅游景物或路人。
全局不可变化：{车体比例、前后灯组、标志、轮毂辐条与颜色、卡钳、附件及安装位置等}。
本侧细节：{逐条列Dxx物理侧别、面板、位置、相对尺寸、图形形状、颜色、文字与方向}。
对侧规则：{该侧哪些图案不同；禁止复制/镜像另一侧；看不到的图案不能移到可见面}。
状态：{用户确认后的门把手、灯光、车窗、车门、前轮方向及车顶附件状态}。
文字：{仅来自清晰原图或用户确认的精确字符串；逐字保持，字体轮廓仍以原图为准}。
保持车身上的文字为正确阅读方向，不镜像、不翻译、不改写，不增删任何贴纸/拉花，不改变轮毂辐条或车顶箱。
画面无标签、无箭头、无网格线、无水印、无额外车辆；不加运动模糊或戏剧光。
```

工具需要英文描述时，可翻译摄影与限制描述，车身文字保持原语言原样。无法读取的文字不填猜测字符串：manifest 使用 `status=uncertain`、空 `text_exact`，在 `lock` 中注明不可读；若为身份关键项目，等待视觉素材再生成该细节。

## 原图细节卡模板

```text
D03｜车辆右侧｜后侧窗
证据：S08；原图局部，不是AI重绘；{旋正后的bbox}
文字：{text_exact} / 不清晰，待确认
位置：{面板、锚点、相对尺寸；无法测量时注明估计}
锁定：{图案轮廓、颜色、文字方向、大小、朝向、邻接关系}
可信状态：已确认 / 待确认
不对称差异：左侧对应部位是D04，禁止互换
```

细节放大只改善观看尺寸，不能创造新证据。精确字形/拉花边缘优先用原设计文件或清晰近摄。卡钳位置按轮心前/后或车辆坐标记录，不按图片左/右；轮毂辐条形状与数量都要对照。

## 局部修正模板

```text
编辑目标：{实际生成图路径/图像角色}。
证据参考：{真实S编号/D编号与物理侧别}。
仅修正：{明确错误部位及其应有位置/形状/精确文字}。
保持：本图车体比例、观察角度、透视、车漆、所有其他已通过细节、光线、背景与裁切。
不得将对侧图案复制到本侧，不得改变已通过的车轮、附件或灯组。
修正后仍输出完整单车无标签图。
```

区分编辑目标与辅助参考，不把参考原图整张替换成结果。每次只修一个问题；完成后重查全车。

## 人工核验记录

在每张 `views[].qa_note` 或项目记录中保存以下结论，不能由排版脚本替代：

| 项目 | 检查方法 | 不通过示例 |
|---|---|---|
| 视角/完整性 | 正前后居中、正侧完整、斜视侧别正确，车体/轮胎/顶箱有留边 | 缺轮、车头切掉、两个右侧被误标左右 |
| 车体结构 | 对照窗线、灯位、前后悬、门缝、车顶比例 | 旅行车变SUV、灯/保险杠换款 |
| 车漆/材质 | 中性光下视觉一致，允许物理反射差异 | 蓝灰变纯白/深蓝、金属漆变哑光 |
| 左右图案 | 每侧与本侧原图/D编号比对，跟随所属面板 | 窗贴互换、拉花跨错门缝、新增图案 |
| 标志/文字 | 原图与结果近看，逐字、方向、布局一致 | 拼错、乱码、镜像、替换品牌标 |
| 轮毂/卡钳 | 检查辐条数量/形状、轮圈/中心、前后位置 | 七辐变五辐、卡钳颜色/方位错 |
| 附件 | 顶箱形状、支架、贴纸与安装关系 | 顶箱消失、换款、支架悬空 |
| 状态 | 对照已确认的门把手、车灯、车窗 | 把手、灯光或窗态自行变化 |
| 细节证据 | 原图bbox、侧别、标签、定位框一致 | 裁错部位、小字重画后标成已确认 |

使用 `通过/待确认/失败`，注明原图或用户确认依据。不能用未经定义的“相似度99%”或生成模型的自述替代查看。

用户确认某状态后更新档案和受影响视图，其他待答保持待答；未答不能因超时推断同意。批准八视图不能证明后续视频逐帧一致性。

## 视频参考用法

```text
参考A：完整八视图看板；本镜头以其中右前45°格为主要角度依据，锁定同一车辆整体身份、车漆、轮毂与顶箱。
参考B：单张细节约束看板；以D03右后侧窗和D01右前门区域锁定本侧窗贴、黄色徽章的图案、文字方向、位置和比例。
车辆左/右基于坐在车内面向车头。相机从右前绕到右后时，图案随各自车身面板转动且遵守遮挡；不滑动、不变字、不复制到另一侧。
不把看板标签、箭头、格线或解释文字画到车上或场景里。
```

图像数量、参数、分辨率、参考强度以实际视频模型为准。本参考文件只负责车辆资产；是否继续视频替换按主 SKILL.md 的分支选择与看板确认执行。
