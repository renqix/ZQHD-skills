# Seedance 2.5 视频 Skill

编写与接收生成提示词时，沿用 [提示词初稿与实际入口超限处理](../zqhd-video-ai/components/workflow/references/prompt-authoring-and-limits.md)：先按所选模型格式准确书写，结合参考图去掉无效重复；只有真实入口超限才返回二次语义检查。保留本技能的素材、模式和生成授权边界。

这是 Seedance 2.5 专用的长叙事、参考与编辑 Skill。它先写可验收的时间轴和参考角色，再输出可复制提示词与当前平台待核对参数；不会把“官方宣布支持”当成某个账号已经开放，也不会把生成完成当成内容通过验收。

## 1. 适用边界

适用于：Seedance 2.5 的文字生视频、图片/视频/音频参考、30 秒内长叙事、多轮视频延长、时间戳级编辑、绿幕、摄像机视角编辑、参考编辑、白模/黏土空间控制、连续转场和汽车广告。

不适用于：用户明确指定的 Seedance 2.0 参数或 2.0 专属接口。不要把 2.0 的旧版数量、时长、模型 ID 或短镜头默认值写进 2.5；如果用户只说“Seedance”且版本不明，先确认版本。

## 2. 2.5 官方事实与动态参数

字节 Seed 官方 2.5 发布文（2026-07-31）确认：单次最长 30 秒并支持多轮延长；单次参考最多 30 张图片、10 段视频、10 段音频；支持精确到时间戳的音视频编辑；强化绿幕、摄像机视角和基于参考的编辑；官方示例还展示白模/黏土空间结构参考。

- 上述是官方发布层能力，不代表所有平台、模式、账户和地区都开放；执行前检查当前入口。
- 社区常见“4–30 秒”“30–180 秒超长模式”“Smart Edit/Advanced Edit/Video Edit 的具体入口”等，必须标为社区或平台工作流，不能升级为官方统一规范。
- 比例、清晰度、声音、延长长度、编辑入口、文件格式、模型 ID、价格和权限，必须以当次平台界面/API 为准。

写作先读 [references/prompt-writing.md](references/prompt-writing.md)，按素材指代、一句话概述、顺序情节与贯穿要求组织；官方方舟编辑/延长的角色和参数单独核对。查来源读 [references/sources.md](references/sources.md)；汽车读 [references/automotive.md](references/automotive.md)；时间轴、延长或编辑读 [references/timeline-edit.md](references/timeline-edit.md)。

## 3. 默认工作流

### 第一步：版本与任务锁定

先写 `Seedance 2.5` 和工作流类型：T2V、I2V、R2V、首尾帧、延长、局部编辑、绿幕、视角编辑或白模/黏土参考。若当前平台模型选择不是 2.5，暂停并报告冲突。

### 第二步：分配参考素材角色

```text
@Image 1 只负责主车外观身份与材质。
@Image 2 只负责内饰布局与光线。
@Video 1 只负责前一段已确认画面和延长起点/运镜。
@Clay Render 1 只负责空间、机位、阻挡、轨迹和节奏。
@Audio 1 只负责对白、音色或环境声。
```

每个引用都要写“不负责什么”，防止多模态素材互相泄漏。官方允许更多素材不等于应该全部上传；冲突素材先删减或明确优先级。

### 第三步：编写时间轴合同

用自然段落控制时间，不把每 0.5 秒都塞一个动作：

```text
起始状态：主体、空间、镜头、光线、声音
0–5s：建立空间与主体，触发主要动作
5–10s：完成一个关键变化，镜头连续覆盖
10–15s：结果/反应，声音与画面同步
结束状态：主体、车位/人物姿态、镜头方向、声音尾点
```

长叙事先规划全局，实际生成时逐段确认；下一段只能从上一段已验收的最后状态继续。

### 第四步：输出提示词包

1. `版本与工作流`：明确 2.5 和 T2V/I2V/R2V/延长/编辑等。
2. `参考素材合同`：每个素材控制什么、排除什么。
3. `[Positive]`：时间轴、主体、动作、景别、主运镜、光线、声音和结束状态。
4. `[Negative]`：车型漂移、空间跳变、动作重演、首尾不连续、错误编辑范围、自动字幕、水印和未授权内容。
5. `当前平台参数`：区分官方能力、当前平台已确认值、社区工作法和待核对值。
6. `验收与下一步`：关键时间点、编辑边界、接缝、声音和品牌检查；实际生成按单段门控。

`[Positive]` / `[Negative]` 是本地交付段名，不是官方必填字段；当前入口没有独立负面字段时将必要约束合入正文。`@Clay Render 1` 等是职责示意，实际白模仍上传到入口支持的视频/图片槽位，不虚构专属参数。

## 4. 2.5 汽车专项

汽车任务读取 [references/automotive.md](references/automotive.md)：先建立车辆身份卡，再让白模/黏土控制空间和轨迹，让外观图控制车，让内饰图控制座舱。

- 外观、内饰、运动和空间参考分工明确；不让运镜视频把自己的车型带进来。
- 每段时间轴固定车头朝向、行驶方向、车道、镜头侧别、光向、背景锚点、车漆、灯组、轮毂和内饰状态。
- 换电/装配等复杂机械动作写出起始、承托/接触、部件移动、对位、锁定和收束；若一段时间轴无法稳定展示关键接触，就拆段或使用白模/局部编辑。
- 车标、车牌、仪表和中控文字需要逐字正确时，规划后期叠加或局部编辑，不把模型生成文字当成已验证资产。

## 5. 延长、编辑与失败重写

- 延长：明确从 `@Video 1` 最后一帧/最后声音起点继续，只生成后续，不重演已发生动作，不切回开头，不改变画幅和主体朝向。
- 编辑：只修改用户点名的变量和时间区间，其余身份、空间、动作顺序、光线、声音和风格保持不变。
- 车型漂移：提高外观多视图优先级，减少竞争车型，必要时先局部编辑静态车再延长运动。
- 时间轴跳变：减少同时发生的动作，把自然段改成一个关键变化，复述上一段尾帧状态。
- 延长接缝：检查第一帧、车速、光向、环境声和主体身份；接不上时从更短的已验收尾段延长。
- 对白错位：写清说话人、引号台词、时机、停顿和环境声；未要求的旁白、音乐、字幕关闭或后期处理。
- 水印/字幕/品牌错误：列具体禁项；强制平台水印只能核对导出权益，不能承诺 Skill 自动去除。

同类失败两次后提出调整方法：减少参考、缩短时间轴、拆段、换白模/黏土、改局部编辑或后期处理。记录保留项、唯一改动和仍未验证项。

## 6. 生成门控与完成标准

实际提交前展示 brief、时间轴、引用角色、平台参数和验收标准。用户已明确模型、规格、数量与生成授权时直接按范围提交，不重复确认；超出费用或其它授权范围时再询问。LibTV 不因无法查询报价而阻塞已授权生成。用户要求先看第一段时，不得自动生成全片：单段提交—等待终态—检查接缝/画面/声音—用户确认—再继续。

最终报告区分：官方能力依据、当前平台实际参数、任务是否完成、文件是否导出、汽车一致性/编辑边界/声音是否通过，以及未验证项目。

调整方法只作为候选；改变模型、时长、镜头数量或再次付费生成须在本轮明确授权内，提交不明时先查原任务，不因重写提示词自动重投。
